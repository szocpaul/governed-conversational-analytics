# Phase 1 Data Model: Synthetic Ticket Texts

**Feature**: 009-synthetic-ticket-texts | **Date**: 2026-10-12 | **Spec**: [spec.md](spec.md)

## 1. Generated Ticket Text (domain entity)

Three synthetic English text fields belonging to one ticket, generated by
the pinned local model from the ticket's structured columns.

| Field | Type (artifact) | Type (DB) | Rules |
|---|---|---|---|
| ticket_id | int (required) | — (join key) | Must exist in pinned tickets.csv; exactly once per artifact |
| short_description | string (required, non-empty) | `text` NULL | Exactly 1 sentence, <= 100 chars (prompt targets ~80); names the problem + key detail |
| description | string (required, non-empty) | `text` NULL | 2-4 sentences, <= 600 chars; reporter context, scope, trigger, impact; priority-appropriate wording |
| resolution_notes | string or null (key always present) | `text` NULL | 1-3 sentences, <= 450 chars when present; NULL exactly when the ticket is open (`closed_at` empty) |

**Consistency invariant**: text must not contradict the ticket's structured
columns (category/sub_category lexicon check, deterministic — research R5).

## 2. Generation Artifact (file entity)

`data/raw/tickets_texts.jsonl` — pinned, versioned, committed after human
approval.

- One JSON object per line: `{"ticket_id", "short_description",
  "description", "resolution_notes"}` (all four keys always present).
- Line order = pinned `data/raw/tickets.csv` row order (2057 lines).
- SHA-256 recorded in `texts-manifest.json`; treated as immutable once
  `human_review.approved == true`. Any change = new `artifact_version` +
  full regeneration (never partial).

**State transitions**: `(absent)` -> `generating` (checkpoint exists) ->
`generated` (artifact written, checkpoint deleted) -> `validated`
(deterministic suite 100% pass) -> `approved` (human_review recorded,
artifact frozen) -> `imported` (present in DB, import manifest extended).
Only `approved` artifacts may be imported. A `superseded` state applies to
older versions after regeneration; superseded artifacts are retained under
a versioned name if regeneration ever occurs.

## 3. Provenance Manifest (file entity)

`data/raw/texts-manifest.json` — committed alongside the artifact.

| Field | Content |
|---|---|
| artifact_version | e.g. `"1"` (bumped on regeneration) |
| artifact_path / artifact_sha256 / row_count | artifact identity |
| model_id | exact pinned API model ID from `GET /v1/models` |
| llama_cpp_version | server version reported by the endpoint, if exposed; otherwise recorded as `"unreported"` with the verification date |
| temperature | `0` |
| seed | integer used for all calls |
| cache | `false` |
| prompt_version | `PROMPT_VERSION` from `app/ai/text_generation.py` |
| dspy_version | e.g. `"3.4.0"` |
| generator_script_sha256 | SHA-256 of `scripts/generate_ticket_texts.py` (plus `app/ai/text_generation.py` hash) |
| batch_config | `{"batch_size": 5, "max_retries": 2, "batches": 412, "retries_used": <n>}` |
| created_at | ISO-8601 UTC of run completion |
| validation | `{"suite_passed": true, "checks": [...], "validated_at": <iso>}` |
| human_review | `{"approved": false}` initially; the HUMAN sets `approved: true, reviewer, reviewed_at, sample_notes` after per-category review (MANUAL GATE) |

## 4. Database changes (itsm.tickets)

Additive columns, marked generated (schema comment `-- GENERATED (feature 009,
synthetic text from pinned artifact data/raw/tickets_texts.jsonl)`):

```sql
short_description text NULL,
description       text NULL,
resolution_notes  text NULL
```

- Nullable because pre-import databases legitimately lack texts; no CHECK
  constraints on text content (validation lives in the deterministic suite,
  not the DB).
- Added to the CREATE TABLE definition AND via idempotent
  `ALTER TABLE ... ADD COLUMN IF NOT EXISTS` (research R6).
- No new indexes in this feature (text search indexes belong to the later
  hybrid-search feature).
- All 19 pinned columns keep their pinned values; import still verifies the
  pinned CSV checksums first.

## 5. Import-manifest extension (artifacts/import-manifest.json)

One new top-level key `generated_texts` (schema in
contracts/artifact-schemas.md). Existing `dataset` / `import` / `notes`
keys are structurally unchanged; feature-001 tests keep passing (research
R8).

## 6. Checkpoint (transient file entity)

`artifacts/tickets_texts.checkpoint.jsonl` — append-only, same line schema
as the artifact; deleted on successful completion; never committed; loaded
on startup for resume (research R3).

## Relationships

- `tickets_texts.jsonl`.ticket_id -> `tickets.csv`.ticket_id (1:1, total
  both ways — enforced by the validation suite and the import).
- `itsm.tickets` generated columns <- artifact (upsert on ticket_id).
- `texts-manifest.json` 1:1 artifact version; referenced by
  `artifacts/import-manifest.json.generated_texts` (path + hashes).
